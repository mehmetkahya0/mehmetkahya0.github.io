TempMail: a disposable inbox in vanilla JavaScript

How TempMail turns the Guerrilla Mail API into a fast, multi-inbox web app with no framework and no backend, and what it takes to safely render emails from strangers in the browser.

Every "sign up to download" form asks for an email address it will spam forever. TempMail gives you a throwaway inbox in one click: a real address that receives real mail, which you can read, star and delete, then simply forget. It is my second most-starred project, with more than 180 stars and 80 forks.

The interesting constraint is that there is no backend of my own. TempMail is a static site on GitHub Pages: HTML, CSS and around 2,400 lines of vanilla JavaScript talking directly to the Guerrilla Mail API. This post is about how that works, and about the part people underestimate: displaying HTML email from strangers safely.

Architecture: a static client on top of a public API

Guerrilla Mail exposes a simple AJAX API where every call is ajax.php?f=<function> and a session token (sid_token) ties requests to one mailbox. TempMail uses a handful of functions:

CallUsed for
get_email_addressCreate a new inbox and get its session token
set_email_userPick a custom username and one of seven domains
get_email_listPoll the inbox
fetch_emailLoad a full message body
fetch_attachmentDownload attachments
del_emailDelete one or many messages

Everything else (sessions, caching, tagging, the UI) lives in the browser. Configuration such as timeouts, retry counts, storage keys and the domain list sits in one config.js, so behaviour can be tuned without touching the logic.

Network calls that fail gracefully

A free public API will sometimes be slow or down. Every request goes through a small wrapper that adds a hard timeout with AbortController, so a hanging request never freezes the UI. On top of that, startup retries with a growing delay, a failed address generation retries once by itself, and an online/offline indicator tells you what is going on: 

async function fetchWithTimeout(url, options = {}, timeout = CONFIG.REQUEST_TIMEOUT) {
  const controller = new AbortController();
  const timeoutId = setTimeout(() => controller.abort(), timeout);
  try {
    const response = await fetch(url, { ...options, signal: controller.signal });
    clearTimeout(timeoutId);
    return response;
  } catch (error) {
    clearTimeout(timeoutId);
    if (error.name === 'AbortError') throw new Error('Request timed out');
    throw error;
  }
}

Rendering email from strangers, safely

An inbox is an unusual web app: its main content is HTML written by anyone on the internet. Dropping an email body into innerHTML would let any sender run JavaScript on my domain. TempMail sanitizes every body before it touches the page:

  1. Parse the HTML with DOMParser into an inert document. Nothing executes during parsing.
  2. Remove dangerous elements outright: script, iframe, object, embed, form and form controls.
  3. Strip every on* event-handler attribute and any attribute whose value starts with javascript:.
  4. Rewrite relative image and link URLs to absolute Guerrilla Mail URLs, and force external links to open in a new tab with rel="noopener noreferrer".
const doc = new DOMParser().parseFromString(html, 'text/html');

['script', 'iframe', 'object', 'embed', 'form', 'input', 'textarea', 'select']
  .forEach(tag => doc.querySelectorAll(tag).forEach(el => el.remove()));

doc.querySelectorAll('*').forEach(el => {
  for (const attr of [...el.attributes]) {
    if (attr.name.startsWith('on') || attr.value.startsWith('javascript:')) {
      el.removeAttribute(attr.name);
    }
  }
});

Plain-text fields such as subjects and sender names go through a separate escape function instead, because text should never be interpreted as markup in the first place.

Lesson A block-list sanitizer is a solid first line of defence, but HTML has many dark corners (SVG, srcdoc, CSS url() tricks). If I hardened it further, I would render bodies inside a sandboxed <iframe srcdoc> without allow-scripts, so even a missed vector couldn't execute.

Multiple inboxes, one tab

Version 4 added tabbed mailboxes: up to five disposable addresses at once, each with its own session token, countdown timer and refresh settings. Sessions are stored as an array in localStorage under temp_mail_sessions_v4, and older single-session data is migrated automatically on first load, so upgrading never loses an inbox. The five-session cap is deliberate. Each inbox polls the API, and an unbounded number of tabs would quietly hammer a free service.

New-mail detection keeps a set of known message ids per inbox. When a poll returns an id that isn't in the set, the app knows it is genuinely new and can raise a browser notification (if you granted permission) instead of re-announcing old mail after every refresh.

Small features that make it feel fast

  • Command palette (Ctrl/⌘ + K) with fuzzy search and full keyboard navigation: copy the address, switch inboxes, regenerate, clear, change language or theme.
  • Semantic tags. Incoming mail is classified by keywords in the subject and sender, in both English and Turkish, into Verification (codes, OTPs, activation links), Security (logins, 2FA, resets), Testing and Marketing. A "Verifications" filter chip shows the one email you usually came for.
  • Starring that persists across visits, and quick filters for All, Starred and Verifications.
  • QR code of the address, so you can use it on your phone.
  • Bilingual UI. A dictionary-based TR/EN layer picks the language from navigator.language and remembers your choice.

The classifier is deliberately simple: ordered keyword checks, with verification checked first because it matters most. Simple rules are predictable, fast and easy to extend with a new language. That beats an opaque model for a feature whose job is to surface one-time codes.

Design without a framework

The interface is glassmorphic cards over an animated "aurora" background with a subtle SVG film-grain overlay. The colours are HSL-based CSS variables, which makes the dark/light theme switch a matter of swapping a few tokens. No framework and no build step means the page loads fast from GitHub Pages and the code is readable by anyone who opens DevTools, which is part of why so many people fork it.

Dealing with clones

Popularity has a downside: copies of the site re-hosted under other names. TempMail includes layered client-side guards that check the hostname and a license flag at startup and periodically at runtime, with a ?dev=1 escape hatch for local testing. I'm realistic about what this is: client-side checks are a deterrent, not real protection, because anyone determined can strip them. The license and clear attribution do the real work.

What I learned

  • Treat every byte from the network as hostile, especially when the product's whole purpose is receiving mail from strangers.
  • Vanilla JavaScript scales further than people think, as long as you keep configuration, networking, state and rendering in clearly separated pieces.
  • Be a good citizen to the API you depend on: timeouts, bounded retries and a cap on concurrent pollers.
